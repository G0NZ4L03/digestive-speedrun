# Plan de Actuación - Digestive SpeedRun Tracker v1.2

**Fecha:** Enero 2025
**Versión:** v1.2.0
**Objetivo Principal:** Integración con Gemini API para análisis clínico automatizado
**Enfoque:** Opt-in, mínima fricción, privacidad por defecto

---

## 📋 Resumen Ejecutivo

### Cambio de Arquitectura
**Antes (v1.1):**
```
Frontend (React) → localStorage → Generar prompt → Copiar manual → Pegar en Gemini
```

**Después (v1.2):**
```
Frontend (React) → localStorage → Backend API (opcional) → Gemini API → Resultado en UI
                                      ↓
                                 (Si usuario opt-in)
```

**Nota:** Para mantener privacidad por defecto, implementaremos dos modos:
1. **Modo Local (default):** Genera prompt y copia al portapapeles (como v1.1)
2. **Modo IA (opt-in):** Usuario configura API key, app consulta Gemini directamente

### Ventajas del Enfoque
- ✅ Mantenemos privacidad por defecto (modo local)
- ✅ Usuario elige usar IA (opt-in)
- ✅ Cambio de arquitectura mínimo (no backend obligatorio)
- ✅ API key se guarda en localStorage (en dispositivo del usuario)
- ✅ Sin coste de backend para nosotros
- ✅ Implementación rápida (3-5 días)

## 🎯 Objetivos Específicos

### Objetivo 1: Configuración de API Key
- **Qué:** Añadir sección en Ajustes para que el usuario configure su API key de Gemini
- **Cómo:** Input de texto con toggle para activar/desactivar modo IA
- **Seguridad:** API key se guarda en localStorage (encriptada opcionalmente)
- **Validación:** Verificar que la key es válida con un test call

### Objetivo 2: Integración con Gemini API
- **Qué:** Endpoint para consultar Gemini directamente desde el frontend
- **Cómo:** Fetch a `https://generativelanguage.googleapis.com/v1beta/models/gemini-pro:generateContent`
- **Seguridad:** API key se envía en headers (standard OAuth flow)
- **Error handling:** Graceful degradation a modo local si falla

### Objetivo 3: Nuevo componente de Análisis IA
- **Qué:** Panel dedicado para análisis con IA
- **Cómo:** Componente que muestra resultados de Gemini de forma estructurada
- **UI:** Cards con insights, recomendaciones, tendencias
- **Fallback:** Si no hay API key, muestra prompt para copiar (como v1.1)

### Objetivo 4: Prompt Mejorado para Gemini
- **Qué:** Prompt más sofisticado que aprovecha capacidades de Gemini
- **Cómo:** Contexto conversacional, análisis más profundo, recomendaciones específicas
- **Mejoras:**
  - Incluir contexto clínico detallado
  - Pedir análisis de correlaciones
  - Pedir recomendaciones personalizadas
  - Pedir detección de patrones

### Objetivo 5: UX Opt-in
- **Qué:** UX clara para que el usuario entienda el flujo opt-in
- **Cómo:**
  - Banner informativo en Dashboard
  - Tooltip explicando qué datos se comparten
  - Confirmación antes de enviar a IA
  - Opción para borrar API key del dispositivo

## 🔒 Consideraciones de Seguridad

### Privacidad
- **Por defecto:** Todo local, nada se comparte
- **Opt-in:** Usuario decide configurar API key
- **Transparencia:** Mensaje claro de qué datos se envían
- **Control:** Usuario puede borrar API key en cualquier momento

### Datos que se envían a Gemini (si opt-in)
- Logs de adherencia y síntomas
- Tipo de comida
- Notas
- Fecha/hora de registros
- **NO:** Identificadores personales, ubicación, metadata

### Almacenamiento de API Key
- **Dónde:** localStorage (`digestive-gemini-key`)
- **Encriptación:** Opcional (Base64 mínimo, o más robusto si se prefiere)
- **Exposición:** Solo visible en configuración (input type="password")

### Validación de API Key
- Test call simple con prompt mínimo
- Si falla: Mostrar error y no guardar
- Si éxito: Guardar y activar modo IA
