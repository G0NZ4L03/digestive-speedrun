# Plan de Actuación - Digestive SpeedRun Tracker v1.2

**Fecha:** Enero 2025
**Versión:** v1.2.0
**Objetivo Principal:** Integración con Gemini API para análisis clínico automatizado
**Enfoque:** Opt-in, mínima fricción, privacidad por defecto

---

## 📋 Resumen Ejecutivo

### Cambio de Arquitectura
**Antes (v1.1):**
```
Frontend (React) → localStorage → Generar prompt → Copiar manual → Pegar en Gemini
```

**Después (v1.2):**
```
Frontend (React) → localStorage → Backend API (opcional) → Gemini API → Resultado en UI
                                      ↓
                                 (Si usuario opt-in)
```

**Nota:** Para mantener privacidad por defecto, implementaremos dos modos:
1. **Modo Local (default):** Genera prompt y copia al portapapeles (como v1.1)
2. **Modo IA (opt-in):** Usuario configura API key, app consulta Gemini directamente

### Ventajas del Enfoque
- ✅ Mantenemos privacidad por defecto (modo local)
- ✅ Usuario elige usar IA (opt-in)
- ✅ Cambio de arquitectura mínimo (no backend obligatorio)
- ✅ API key se guarda en localStorage (en dispositivo del usuario)
- ✅ Sin coste de backend para nosotros
- ✅ Implementación rápida (3-5 días)

## 🔒 Consideraciones de Seguridad

### Privacidad
- **Por defecto:** Todo local, nada se comparte
- **Opt-in:** Usuario decide configurar API key
- **Transparencia:** Mensaje claro de qué datos se envían
- **Control:** Usuario puede borrar API key en cualquier momento

### Datos que se envían a Gemini (si opt-in)
- Logs de adherencia y síntomas
- Tipo de comida
- Notas
- Fecha/hora de registros
- **NO:** Identificadores personales, ubicación, metadata

### Almacenamiento de API Key
- **Dónde:** localStorage (`digestive-gemini-key`)
- **Encriptación:** Web Crypto API (AES-GCM) - encriptación real para seguridad comercial
- **PIN de usuario:** Se pedirá al configurar para derivar key de encriptación
- **Exposición:** Solo visible en configuración (input type="password")
- **Seguridad:** Protege contra acceso malicioso, preparado para market futuro

### Validación de API Key
- Test call simple con prompt mínimo
- Si falla: Mostrar error y no guardar
- Si éxito: Guardar y activar modo IA

### Rate Limiting y Token Tracking
- **Límite gratuito:** 15 requests/min, 1500 requests/día
- **Rate limiting local:** Máximo 10 requests/hora para evitar uso accidental
- **Token tracking:** Monitorizar uso de tier gratuito
- **Avisos visuales:**
  - "⚠️ Quedan pocos tokens gratuitos hoy"
  - "ℹ️ Tokens reinician en X horas"
  - "🚫 Límite alcanzado, espera X minutos"
- **Representación visual integrada:**
  - Barra de progreso de tokens usados
  - Contador: "120/1500 tokens usados hoy"
  - Indicador de tiempo restante para reset
- **Bloque:** Si se excede límite gratuito, bloquear hasta reset
- ** Política:** No pagar nunca, usar solo tier gratuito

## 🎯 Conclusión

Este plan implementa la integración con Gemini API de forma:
- **Segura:** Privacidad por defecto, opt-in claro, encriptación Web Crypto API
- **Flexible:** Usuario elige modelo (gemini-1.5-pro default, gemini-2.0-flash opcional)
- **Profesional:** Markdown renderizado, rate limiting, token tracking
- **Simple:** Cambio de arquitectura mínimo (sin backend obligatorio)
- **Escalar:** Prepara terreno para market futuro (seguridad comercial)
- **Documentada:** Todo queda registrado para el futuro

**Decisiones del Usuario:**
1. Modelo configurable (default: gemini-1.5-pro, opcional: gemini-2.0-flash)
2. Markdown con react-markdown (formato bonito, visual, emojis)
3. Historial: guardar solo último análisis (futuro: más)
4. UX: First-run wizard + card no intrusivo (educación al usuario)
5. Rate limiting con bloqueo (solo tier gratuito, visual de tokens)
6. Error handling híbrido (detallado común, genérico raro)
7. Encriptación Web Crypto API (seguridad comercial, PIN del usuario)

**Rumbo tomado:** Hacia una app más inteligente pero manteniendo los valores de privacidad, simplicidad y seguridad comercial que la hacen especial y lista para el futuro.
